# Handoff: WP-CONFIG Implementation Ready

## Context

The design specification for WP-CONFIG (Local Configuration Management) is complete. This work package enables a seamless first-run experience with automatic system profiling and intelligent model recommendations. It's a high-priority MVP enhancement that improves user onboarding.

**Why now:** Users currently need to manually download models and configure paths. This creates friction for new users and doesn't leverage system capabilities optimally.

- Use `directories` crate for platform config paths
- TOML format for config file
- Tier-based model recommendations

## Deliverables Expected

### Code
1. `crates/lexicon-core/src/config/` module
   - `mod.rs` — Module exports
   - `schema.rs` — Config structs with serde
   - `profiler.rs` — SystemProfiler implementation
   - `wizard.rs` — FirstRunWizard implementation

2. CLI commands in `crates/lexicon-cli/`
   - `lexicon config show` — Display current config
   - `lexicon config set <key> <value>` — Modify config
   - `lexicon config profile` — Re-run system profiling

3. Integration with existing `transcribe` command
   - First-run detection and wizard trigger
   - Config loading on startup

### Tests
- Unit tests for config load/save
- Unit tests for tier detection logic
- Integration test for first-run flow (headless mode)

### Documentation
- Update CLI `--help` with new commands
- Document config file location and schema

## Acceptance Criteria

- [ ] System profiler detects RAM, CPU, GPU, and disk space
- [ ] Profile tier correctly categorizes system capabilities
- [ ] Model recommendations match system tier
- [ ] First-run wizard runs when no config exists
- [ ] Config file saved in platform-appropriate location
- [ ] Existing config loaded on subsequent runs

- [ ] Headless/non-interactive mode works for CI/automation

## Implementation Hints

1. **Start with profiler** — `sysinfo` crate handles most hardware detection
2. **Config schema first** — Define the TOML structure before implementing load/save
3. **Test tier logic** — Edge cases around RAM thresholds are important
4. **Headless mode** — Essential for CI; use environment variable or `--headless` flag

**Existing code to leverage:**
- `WP-MODEL` already has model download infrastructure
- `WP-CORE` has logging and error handling patterns
- `WP-CLI` has clap argument parsing patterns
